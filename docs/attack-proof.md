# Holdt attack proof

Generated by `npm run prove` (scripts/prove-attacks.mjs) at Oct 17, 2026, 12:00 AM MT, on commit bea21e2.
Attacks live in test/attacks.test.ts and run against the same Worker code `wrangler dev` serves, with a mock iCloud and an attacker-controlled server on localhost.

Method: every protection is switched off in a scratch copy (the real source is never edited), the matching attack is run, and it must now succeed. "Layered" rows switch off one layer and show the next one still stops the attack. Then every protection is back on and every attack is refused again.

## What the server cannot prove
The server can't see the conversation, so it can't prove the user said yes. A model that follows injected text could still prepare and commit a new event on a writable calendar. The design caps that damage: no delete or invite tools exist, events from other people can't be edited, every write is one exact previewed change, nothing leaves iCloud through Holdt, and read-only is one setting away. Event text is labelled as untrusted data in every result and in the server instructions.
